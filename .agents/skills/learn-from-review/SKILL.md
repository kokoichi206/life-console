# レビュー指摘の反映

対象 PR・コメント・会話と実コードを確認する。PR を読む場合はリポジトリと番号を確定し、指摘本文・対応 diff・現状を分ける。相手の指摘を無条件に正しいとみなさない。

再発する原因と、既存の仕組みで検出できなかった理由を特定する。単発の typo、当該機能だけの要件、既に規約で扱っている内容を汎用ルールへ増やさない。

| 原因 | 反映先 |
| --- | --- |
| 振る舞いの回帰 | 対象機能のテスト |
| 構文・型情報で検出できる違反 | `packages/eslint-config/rules/`。既存 README の RuleTester 手順を使う |
| 文脈を読む必要がある設計判断 | `docs/agent-rules/` の該当ルール |
| 複数段階の作業での抜け | `.agents/skills/` の該当スキル |
| 全作業で必要な前提・参照先 | `AGENTS.md`。詳細はルール・スキルに置く |

同じ原因を複数箇所に重複して書かず、既存の正本を更新する。機械化するなら違反例と許容例の両方で検証する。AI 設定の変更後は `pnpm harness:check` を実行する。

採用した変更とその根拠、採用しなかった指摘の理由を報告する。PR 作成・投稿・マージは、それぞれ依頼で許可されている範囲だけで行う。
