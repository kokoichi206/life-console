# 差分のセルフレビュー

`git status --short` と差分を読み、利用者の変更を含む範囲と自分の変更を区別する。PR 全体のレビューなら対象 base を確認して比較する。未追跡の追加ファイルも読む。

差分に関係する観点だけ確認する。

| 対象 | 確認する内容 |
| --- | --- |
| 要件 | 元の依頼の対象・修飾語・終了地点を満たしているか。未回答を推測で閉じていないか |
| API / runner | Result の失敗伝達、検証境界、外部 CLI の引数、認証、ログの公開範囲 |
| 永続化 | migration と既存データ、job lease、再実行、下書きの手動編集・競合検出 |
| UI | 指定 UI との一致、保存後の再表示、URL の復元、編集中の保持、ライト・ダーク・狭い画面 |
| 外部操作 | 送信・GitHub 昇格・agent 起動が許可された対象と範囲に収まるか |
| AI 設定 | 共通正本だけを編集したか、両ツールの参照と呼び出し方が成立するか |

[AGENTS.md](../../../AGENTS.md) から該当ルールと既存ドキュメントを読む。lint の対象は CI に任せ、規約の引用だけで不具合としない。

見つけた問題は再現条件・根拠の位置・利用者への影響を確認する。修正依頼の範囲なら直して必要なチェックを再実行する。レビューのみの依頼では指摘を返す。

完了報告には変更結果、実行した検証と結果、未確認の範囲を簡潔に示す。テスト件数で実操作の証拠を代用しない。
