# Life Console 実装レビュー（Grok）

日付: 2026-09-07

対象: 初期コミット以後の Web、API、runner、共有型、DB、設定例、テスト。秘密情報と個人データを除いたソースのコピーを Grok CLI に渡した。

## 結論

初回は P1 が 4 件、P2 が 5 件で要修正。修正後の再レビューと追加修正の確認で、Grok は「最終 PR 作成可」「新規の重大問題はありません」と判定した。

## 指摘と対応

| 重要度 | 指摘 | 対応 |
|---|---|---|
| P1 | UTC 保存の体重が日本時間の暦日と異なる窓に入る | 日本時間の暦日計算を共有し、既存の UTC 記録にも適用。DB は実際の時刻順に取得 |
| P1 | 実行待ちの返信を中止しても送信される | queued は即 canceled にし、claim から除外。実行前の heartbeat を待つ |
| P1 | 返信成功後に runner が停止すると自動再送され得る | 期限切れの conversation_reply は lost にし、自動再実行しない |
| P1 | schedule の SQLite 日時文字列と ISO 文字列の比較が不正 | 日時生成を ISO に統一し、比較は julianday を使用。到来済み期間だけを処理 |
| P2 | 期限切れの lease を有効と判定する | validate、heartbeat、complete で期限を数値比較 |
| P2 | Chatwork の open task が指定外のルームから入る | open task にも対象ルームの制限を適用 |
| P2 | 下書き取得失敗で取得済みの会話まで隠れる | 会話を残し、下書きの取得失敗と返信状況が未確認であることを表示 |
| P2 | 複数タブから同じ会話の返信を重複依頼できる | 同一会話の実行中・実行待ちの返信作成を SQL で排他。終了後の明示的な再依頼は可能 |
| P2 | lost の表示がなく、中止ボタンが残る | 「結果不明」を表示し、操作可能な状態の定義を共有 |

実画面の追加確認では、同日の複数測定を記録頻度の日数に重複計上する表示も修正した。実測件数はそのまま保持し、記録頻度のみ日本時間の暦日数で計算する。schedule のテストも公開 API が受け付ける skip_if_pending を使用するよう訂正した。この追加差分も Grok が確認した。

## 検証

- `pnpm check`: ESLint、全ワークスペースの型チェック、65 件のテスト、Web/API/runner のビルドが成功。
- `pnpm audit --prod --audit-level high`: 既知の脆弱性なし。
- 新しい回帰テストは、修正前の失敗と修正後の成功を確認。
- 独立したローカル D1 を使用し、ブラウザから日本時間の午前の体重を保存。UTC 保存後も同じ日本時間の日付で表示され、CSV と合わせた 7 暦日平均が一致することを API と表で確認。
- 同日の複数測定を含む架空の 3 件で、記録頻度が 2 / 8 日、25% になることをブラウザで確認。検証用サーバーは終了済み。

## 確認範囲の限界

Grok はソースの静的レビューを担当し、自動テストとブラウザ確認は実装側で行った。外部サービスへの返信送信、実際の agent 実装実行、障害を伴う本番での耐久試験は今回実施していない。

本番への再デプロイ、個人データの変更、runner の本番接続は行っていない。Cloudflare Access の機械認証を含む本番 runner の接続は別途必要。
