# 食事の栄養解析とカロリー同期

## 運動の表示と集計

運動一覧とカロリー収支は DB の保存済みデータを表示し、画面表示では Strava にアクセスしません。定期同期の結果を反映し、『運動を同期』から表示期間の同期を依頼できます。未同期の運動は含まれないことを注記し、初回同期前は運動ゼロとみなしません。体重グラフの『消費カロリー』は、全種目の取得済みカロリーを日本時間・月曜始まりで集計します。未取得・取得不可の件数を併記し、全件未取得の週は欠損として表示します。今週や期間端の週には対象日数を示します。基準消費量は含めず、週を選ぶと同じ期間の運動と食事を確認できます。

カロリー収支は直近 7 日から始め、ボタンで前の 7 日を追加表示します。食事の栄養と運動のカロリーは、表示する 7 日ごとの範囲だけを API から取得します。食事一覧の栄養も読み込んだ食事の日付範囲で取得します。

## 食事の入力と解析

初回の食事登録でカロリーを手入力できます。一覧から開く詳細画面でも変更できます。手入力したカロリーは一覧・詳細・日別合計で優先し、解析済みのたんぱく質・脂質・炭水化物も推定値として表示します。手入力後も個別解析・再解析でき、解析中に手入力してもジョブは継続します。解析結果は手入力カロリーを上書きしません。初回から手入力した食事は、自動予約・一括解析の対象外です。

カロリーが未入力の写真またはメモのある食事を保存すると、その食事の解析ジョブを自動予約します。保存と予約は同じトランザクションで行い、保存リクエストの再送では重複予約しません。Mac の runner が次回のポーリング（既定 60 秒、先行ジョブがあればその後）で処理します。既存の未解析の食事は『未解析の食事をまとめて解析』から処理できます。Mac の runner が停止中ならジョブは待機し、起動後に実行します。結果は画面へ自動反映され、再解析もできます。

## 解析 CLI の設定

runner の `LIFE_CONSOLE_NUTRITION_PROVIDER=codex|claude|gemini` で画像解析だけを切り替えます（既定 `codex`）。変更後は runner を再起動します。`LIFE_CONSOLE_NUTRITION_MODEL` で各 CLI のモデル名も指定できます。Codex の既定は画像入力に対応する低コスト向けの `gpt-5.6-luna`、推論は `low` です。ジョブを実行する時点の設定を使い、他の provider へ自動的に切り替えることはありません。返信生成や coding agent の選択には影響しません。

いずれも Mac の認証済み CLI からサービスへ写真とメモを送り、推論はクラウド側で行います。Codex は `codex login` で認証し、`codex exec --image` と JSON Schema で推定します。ユーザー設定・作業指示・スキル指示・メモリの取り込みを止め、shell・web 検索・連携アプリ・プラグイン・フックを無効にした読み取り専用の実行にします。会話を保存しない `--ephemeral` を使い、画像と結果の一時ファイルは終了時に削除します。保存するモデル名は CLI に指定した ID です。モデルの対応状況は [OpenAI Docs](https://learn.chatgpt.com/docs/models)、モデルの特徴は [Luna の仕様](https://developers.openai.com/api/docs/models/gpt-5.6-luna)で確認できます。

Claude は画像入力を `stream-json` で渡し、ツール・MCP・カスタマイズ・セッション保存を無効にします。Gemini は runner の環境へ `GEMINI_API_KEY` を設定すると API キー認証を使います。キーが未設定なら `gemini` コマンドで認証済みの Google ログインを使います。Gemini CLI の個人アカウント向け提供は [2026-06-18 に終了](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)しており、ローカルの Google ログインも `UNSUPPORTED_CLIENT` で拒否されました。Gemini の実推定は未確認です。[公式の認証手順](https://geminicli.com/docs/get-started/authentication/)に従って利用可能な認証を用意してください。Google ログイン時は OAuth 認証ファイルだけを共有する専用の一時ディレクトリを使い、ツール・MCP・拡張・スキル・フックを無効にして、画像・メモ・実行履歴は終了時に削除します。通常は `~/.gemini` の認証を使い、`GEMINI_CLI_HOME` を設定している場合はその配下の `.gemini` を使います。

## 解析結果の保存と表示

推定値は元の記録と別の既存 `nutrition_estimates` テーブルに保存し、使用モデル、解析日時、画像とメモの入力 hash を記録します。再解析の履歴を残し、手入力がなければ、一覧と日別集計には最新の結果だけを使います。日別合計は日本時間で画面の選択期間内の全記録を集計し、カロリー未記録を 0 kcal として扱わず、手入力・解析済みの記録件数を表示します。手入力の 0 kcal は記録済みです。写真がない記録も、メモがあれば詳細の『栄養を解析』『栄養を再解析』から推定できます。メモだけの記録も自動予約・一括解析の対象です。食品名・料理名が分かれば、分量の指定がない場合も標準的な 1 人前として概算します。メモの量・食べ残し・人数の指定を優先します。食品や料理を特定できない場合は失敗として表示し、以前の解析結果を保持します。

## PFC の表示と割合の計算例

カロリー収支の下に、同じ取得範囲の日別 PFC（たんぱく質・脂質・炭水化物）を表示します。推定結果のある食事だけを合計し、保存済みの食事件数と解析済み件数を分けます。カロリーを手入力した食事でも推定結果があれば PFC を集計します。手入力カロリーだけの食事は PFC 未解析です。推定値が全て 0 g の場合は解析済みとして数え、構成比は表示しません。

g 数は表示時に小数第 1 位までに整形し、構成比は丸める前の合計から計算します。割合は P × 4、F × 9、C × 4 の合計を分母にする概算です。手入力カロリーを分母に混ぜません。日付を選ぶと食事一覧を絞り込み、選択日は本人・共有画面の URL の `pfcDay` に保持します。表示範囲外の選択日はその日の栄養を取得して表示します。『全日を見る』で通常の食事一覧へ戻れます。期間ボタンやグラフで表示期間を変えたときは、選択日を解除します。日付で絞り込むのは食事カードで、日別カロリー表は読み込んだ範囲を保持します。食事カードには P / F / C の g 数を追加し、詳細の写真・メモ・手入力カロリー・推定結果・解析モデル・解析日時・更新・再解析の操作を保持します。

『割合の目安』は、本人の理想値として確定していない計算例です。初期値は体重 70 kg・摂取 2,000 kcal / 日、P は体重 × 2.0 g、F は摂取エネルギーの 25 %、C は残りです。この条件から割合と g 数を算出し、実績の近くに計算例として表示します。計算条件を画面上で変更できますが、変更は保存されません。計算例に実際の体重や基準消費量を自動適用せず、健康上の不足・過剰を判定する基準として使いません。

各栄養素には計算例の量を示す線と差分を表示し、計算例を超えた部分を黄色と斜線で示します。差分は画面上の小数第 1 位までの量同士を比較し、集計値自体は丸めません。未解析の食事がある日は、計算例を超えた解析済み分のみ差を表示し、少ない項目には『未解析あり』と表示します。未解析分が加わっても解析済みの合計は減らないため、正の差だけは表示できます。健康上の過不足や上限の判定ではありません。

『次の日に意識すること』では、計算例に対する差の割合が大きい順に最大 2 項目を表示します。脂質なら調理油・ドレッシングの量、たんぱく質なら主菜の有無など、記録と食事を見直すための確認項目です。未解析の日には少ない項目に対するヒントを出さず、まず未解析の確認を案内します。全て 0 g の日は記録漏れの確認を案内します。記録した食事が全て解析済みでも、未記録の食事や当日の残りの食事は把握できません。数値の差を翌日に補償する量や、本人専用の食事指示は出しません。『この日の食事に絞る』で既存の一覧へ絞り込めます。

確認項目は [厚生労働省の食生活指針](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000128503.html)の主食・主菜・副菜と、[農林水産省の脂質の量・質に関する解説](https://www.maff.go.jp/j/syokuiku/minna_navi/topics/topics4_04.html)を参考にしています。

この数値は個人の理想値を示すものではありません。[ISSN の見解](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/)は、健康な運動実施者の多くについて、たんぱく質 1.4〜2.0 g / kg / 日を示しています。計算例の 2.0 g / kg / 日と脂質 25 % は表示の仮設定です。体組成・活動量・減量ペースに合わせた個別の理想値と区別します。

## 定期実行

既存のスケジュール API で `jobKind: "nutrition_analysis"`、`interval: "daily"`、`payload: {}` を登録すると、未解析の食事を定期処理できます。この変更だけでは本番のスケジュールは追加しません。

消費カロリーの同期も同じスケジュール API で `jobKind: "strava_calories_sync"`、`interval: "every_2_hours"`、`coalescing: "skip_if_pending"`、`deadlineSeconds: 7200`、`payload: {}` を登録します。2 時間ごとに直近 30 日を同期し、初回だけ下限日まで 90 日ずつ遡ります。この変更だけでは本番のスケジュールは追加しません。
